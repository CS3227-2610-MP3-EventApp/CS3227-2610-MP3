## Adequacy and limitations

Success, rejection, exact arithmetic boundaries, unknown/zero, failure preservation, current actor, stale confirmations, no replay, private DTO validation, inert untrusted content and UI lifecycle are executable. This suite observes public UI and independent stateful HTTP fixtures, not real PostgreSQL/provider/browser integration. Backend tests separately own full role/ownership/revocation matrix, stale source/draft/participation CAS, limits/overflow, malformed provider output, races/atomic rollback and persistence. Wrong-scope valid-looking DTO UI rejection is not server authorization evidence.

Deferred to root: actual generated editable line changes, real selected multi-item adoption, real provider schema/source quality, real HTTP/browser generation→edit→adopt, pending/running restart without reseeding, retained migration/cleanup/manual preservation, real keyboard/focus/NVDA/400% zoom and320px reflow. Fixture tests do not establish deployment, production separation or human teammate/summary review. Production/real-data AI remains unauthorized. Test adequacy reviewers should assess these explicit gaps before freezing; later required cases remain test-owner changes, never developer edits.
